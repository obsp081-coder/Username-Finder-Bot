# Username Finder Bot

تطبيق Windows بواجهة عربية لأدوات الأسماء والبحث. فحص Snapchat الحقيقي معطّل ونتائجه محاكاة؛ Roblox يدعم فحصًا أوليًا، وقسم **X — تجريبي** يعتمد على نقطة غير رسمية ولا يضمن نجاح تسجيل الاسم.

شغّل [Start.cmd](Start.cmd) بالنقر المزدوج، أو من PowerShell داخل مجلد المشروع:

```powershell
.\.venv\Scripts\python.exe -m username_finder
```

يمكن تحديد قاعدة منفصلة باستخدام `--database "path\history.db"`. تُحفظ البيانات الافتراضية في `runtime/username_history.db` داخل المشروع. يمنع المشغّل فتح نسختين على القاعدة نفسها.

1. اضبط المصدر والطول والعدد من الإعدادات الأساسية، وافتح «إعدادات متقدمة» للفلاتر والأداء والجدولة والسجل. ثم عاين البحث وراجعه قبل الإنشاء.
2. من «التشغيل»، ابدأ أو أوقف مؤقتًا أو استكمل. تحفظ الإعدادات والمصادر لكل بحث؛ تعديل الشاشة يخص البحث التالي.
3. اعرض الحالات الخمس وصدّر نتائج البحث، أو حمّل بحثًا سابقًا من «السجل». تُسمّى جميع صادرات المحاكاة ببادئة `simulated_`؛ صادرات الوضع الحقيقي منفصلة وفارغة حاليًا.
4. عند الإغلاق يتوقف المحرك بأمان. بعد انقطاع مفاجئ يُستعاد العمل المسجل؛ قد تُعاد محاولة قراءة آمنة إذا انقطع الرد قبل حفظه.

التشغيل والإيقاف اليوميان، ومدة التشغيل الفعلية، خيارات مستقلة. الجدولة تعمل ما دام التطبيق مفتوحًا والجهاز يعمل؛ لا تعيد تشغيل المواعيد الفائتة. لا تُحتسب فترات التوقف أو إغلاق التطبيق ضمن مدة التشغيل. لكل جلسة يومية عداد مدة جديد، وتبقى نتائج البحث السابقة محفوظة.

احفظ إعداداتك في قوالب بأسماء تختارها، مع إمكان التحميل والحفظ باسم آخر وإعادة التسمية والحذف. تظهر علامة للتعديلات غير المحفوظة ويُطلب قرارك قبل تبديل القالب أو الإغلاق. تحميل القالب يغيّر محرر الإعدادات فقط؛ لا يبدأ بحثًا أو يغيّر العملية الجارية أو جدولتها. إذا تغير ملف TXT المرتبط بقالب أو اختفى، أعد اختياره قبل إنشاء البحث. القوالب التي تستخدم التوليد لا تحفظ مسارات TXT غير اللازمة.

نسخ SQLite الاحتياطية **لا تضم ملفات TXT الأصلية**. احتفظ بها؛ تمنع بصمة المحتوى الاستكمال إذا تغير ملف أو مكتبة معانٍ. الاستعادة تحفظ نسخة أمان من السجل الحالي أولًا. يُرقّى المخطط من الإصدار 1 إلى 2 بإضافة جدول القوالب فقط، مع نسخة SQLite احتياطية تلقائية في `runtime/Backups` قبل الترقية. تُرفض الإصدارات غير المعروفة بدل تغييرها.

مكتبات المعاني مجموعات منتقاة صغيرة، بمصادر وإصدارات وتراخيص وبصمات في `username_finder/data/manifest.json`، وتفاصيل متاحة من «حول البيانات». تتضمن 179 عنصرًا قبل إزالة التداخل؛ ليست شاملة. لا توجد مشتقات أو درجات شيوع wordfreq في هذا الإصدار. كل كلمة تمر بالشروط المشتركة، ولا تعني المعاني توفر الاسم. في شرط تكرار «أي رمز» يُعرض حد أعلى للعدد حتى تُطبّق التصفية؛ لا يُعرض كعدد نهائي دقيق.

لإعادة إعداد بيئة جديدة (Python 3.12 أو أحدث، Windows 64-bit)، بعد الإذن بتثبيت التبعيات:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

الأوامر المستخدمة للتحقق:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check username_finder tests tools
.\.venv\Scripts\python.exe -m ruff format --check username_finder tests tools
.\.venv\Scripts\python.exe tools\benchmark.py --sample 1200
```

قياسات المحاكي لا تقيس سرعة سناب أو دقته. حدود المصدر تبقى مستقلة عن إعداد العمال 1–1000. يُفعّل الفاحص الحقيقي فقط بعد إثبات وصول مشروع للقراءة ودلالة الاستجابة بمرجع مستقل؛ 404/403/429 أو غياب ملف أو خطأ شبكة لا تثبت التوفر. راجع [PROGRESS.md](PROGRESS.md) للحالة والاختبارات والعائق المتبقي.

## Roblox — البحث الجماعي التجريبي

داخل قسم **Roblox**، يبقى **الفحص الفردي (الدقيق)** هو الافتراضي، بسرعته وتاريخه وتصنيفاته السابقة. اختر **البحث الجماعي عن الحسابات Bulk (تجريبي)** لعرض مساحة الدليل المستقلة. هذا بحث عن حسابات وليس بديلًا لفحص التسجيل؛ لا يثبت الإتاحة ولا يضمن تصنيف Taken الفردي.

1. اضغط **تحضير العينة محليًا**: تُجمّد مرة واحدة 1000 اسم رباعي فريد، بسحب متساوٍ من `a-z0-9` بواسطة `secrets.choice`، مع رفض التكرار واستبعاد مرشحي manifests التجارب السابقة إن وجدت. تُجمّد أيضًا مقارنة عشوائية من 20 اسمًا من أول 200 قبل أي استجابة. التحضير لا يقرأ قاعدة الإنتاج أو طابورها ولا يبدأ طلبات.
2. افتح **مراجعة العينة والأدلة** وافحص البصمة والأسماء والمعاملات والميزانية. أوقف الفاحصات الخارجية، ثم اختر **تفويض المرحلة 1 — 10 طلبات** وأكّد التفويض. تُرسل أول 200 اسم في عشر دفعات من 20؛ تتوقف المرحلة وتحفظ تقريرًا دون الانتقال تلقائيًا.
3. بعد مراجعة المرحلة الأولى، يمكن تفويض **المقارنة — 20 طلبًا** بصورة مستقلة. تستخدم GET الفردي ومعاملاته ومصنفه الحاليين، ولا تكتب إلى سجل الإنتاج. يعرض التقرير التغطية والاتفاقات المرصودة والاختلافات فقط؛ الاسم غير المقارن ليس اتفاقًا. لا توجد طلبات تشخيص إضافية أو ميزانية خفية.
4. **المرحلة 2 — 40 طلبًا** تحتاج تأكيدًا جديدًا بعد مراجعة دليل المرحلة الأولى؛ تخص 800 اسم المتبقية ولا تعيد أول 200. يمنع أي توقف أو انقطاع أو اختلاف مسجل الانتقال التالي. يُنصح بمراجعة المقارنة قبل تفويض المرحلة الثانية؛ لا يطلق أي زر مرحلتين معًا.

حالات دليل الحساب، المنفصلة عن تصنيفات التسجيل الخمسة:

| الحالة | الدلالة المحدودة |
| --- | --- |
| `CurrentAccountMatchByAPI` | اسم حالي مطابق دون حساسية لحالة الأحرف ومعرّف موجب وعلاقة سليمة؛ ليس Taken التسجيل. |
| `HistoricalOrDifferentCurrentName` | سجل مطلوب أعاد اسمًا حاليًا مختلفًا، بما فيه التمثيلات غير الاعتيادية؛ لا استنتاج للإتاحة أو الحظر. |
| `NoMatchingBulkRecord` | لم يُعد سجل مطابق؛ لا يعني Available. |
| `Unknown` | استجابة أو تسليم لا يسمح باستنتاج آمن. |
| `UnsafeOrContradictoryResponse` | بنية أو علاقة هوية غير سليمة؛ توقف ومراجعة. |

النقل متسلسل إلى `POST https://users.roblox.com/v1/usernames/users` مع `excludeBannedUsers=false`، بمهلة I/O قدرها 10 ثوانٍ، وفاصل لا يقل عن 10 ثوانٍ **بعد اكتمال الرد** قبل الطلب التالي. لا تأخير بعد آخر طلب ولا إعادة محاولة أو وكيل أو مصادقة أو تجاوز قيود. تتوقف أخطاء HTTP والقيود وRetry-After والتحديات والأجوبة غير الآمنة فورًا. تبقى نتيجة الفردي أولية ومنفصلة؛ حالة تطابق حساب مع Invalid/code2 مثل `ig49` تسجل اختلافًا وتوقف المقارنة، ولا تعيد كتابة دليل الحساب.

تُحفظ العينة وسجل append-only متين ومترابط بالبصمات وتقارير بإصدارات داخل **`roblox-bulk-account-lookup/` بجانب قاعدة البيانات**؛ الافتراضي `runtime/roblox-bulk-account-lookup/`. تُسجل نية الطلب قبل الإرسال والرد الخام المنقح قبل التفسير، مع التوقيت والمعاملات والسياسة والمصدر. لا توجد جداول أو migrations أو كتابة لنتائج الإنتاج. **تصدير CSV** يشمل الأسماء غير المحاولة وحقول كل مصدر ومراجع دليله؛ **JSON** يشمل التقرير والأحداث والأجسام الخام الآمنة. لا يستبدل التصدير ملفًا موجودًا. عند تلف ذيل السجل، يتيح العرض والتصدير الجزء السليم مع تحذير وبصمة السجل، ويحظر التشغيل.

قفل Roblox مشترك عند مدخل runner يمنع تزامن Bulk مع الفردي أو تشغيله الليلي/الخلفي على القاعدة نفسها، وكذلك بين عمليات التطبيق التي تستخدم النسخة الجديدة. يفحص Bulk حالة الموفر والموعد المحفوظ قبل التشغيل. لا يتحكم القفل في أدوات خارج التطبيق أو نسخة قديمة؛ أغلقها أولًا. **إيقاف** يلغي الانتظار فورًا ويحفظ الطلب الجاري بعد انتهاء I/O. لا يستأنف الطور المنقطع أو المتوقف ولا يعيد إرسال اسم سبق محاولة إرساله. مؤشر عدم اليقين يبقى بعد انهيار العملية، والتوقف غير الآمن يحظر طلبات Roblox الجديدة حتى تدقيق تقني؛ لا يوجد زر لمسح الحماية أو حذف الدليل لتجاوزها. اكتمال مرحلة سليمة وحده يسمح بتفويض طور جديد.

التقرير يفصل النيات والردود المكتملة وعدم اليقين، وأسماء الطلبات والدفعات والحالات والمقارنات، وزمن النقل والانتظار ومدة حلقات المراحل والمتوسط وp95. مدة مرحلة منقطعة أو انتظار غير مكتمل تبقى مجهولة. فرق الخطة العددي **1000 مقابل 50+20=70 طلبًا** افتراضي لمخرجات مختلفة؛ ليس قياس تسريع أو دقة أو بديلًا للتصنيفات الخمسة. لم تُجرَ تجربة الألف اسم أثناء التطوير؛ يلزم دليل المرحلة الأولى الحقيقي وتفويض المستخدم قبل المرحلة الثانية. أدوات وأدلة CLI السابقة في [دليل التجربة](experiments/roblox-bulk-validation/README.md) تبقى مستقلة.

## X — تجريبي

- توليد أسماء فريدة بطول 5–15 من الحروف والأرقام و`_`، أو إدخال يدوي واستيراد UTF-8 TXT/CSV. يسمح CSV بعمود `username` أو عمود واحد دون عنوان؛ يُرفض الملف متعدد الأعمدة الغامض أو غير المتسق. المعاينة محلية، وتعرض أول 20 مرشحًا وعدد غير الصالح والمكرر والمتجاوز. صحة الصيغة لا تثبت الإتاحة؛ اختلاف توثيق طول 15 يبقى قيدًا معروفًا.
- الفحص متسلسل عبر نفس GET ومعامل `username` ومحلل التجربة، دون مصادقة أو بروكسي أو إعادة محاولة تلقائية. التأخير بعد الاستجابة **5 ثوانٍ افتراضيًا**، والخيارات المحافظة 5/10/15/30. يُحفظ التفضيل وتُثبّت سرعة كل عملية عند إنشائها؛ الاستئناف يعرض الفاصل الفعلي ويحترم الموعد الأطول المحفوظ.
- سجل X مستقل في جداول `x_*` داخل SQLite الحالية، دون نقل أو تعديل سجلات Roblox أو تغيير إصدار المخطط. التجاوز الافتراضي يحسب المكرر والمفحوص سابقًا؛ إعادة فحص الاسم المحدد أو جميع السابق تتطلب تأكيدًا وتحفظ التاريخ والتغيرات. تدعم النتائج التصفية والبحث والتصدير، مع خيار كل الملاحظات التاريخية وتحذير الإتاحة الأولية داخل CSV.
- «إيقاف» يحفظ المعلق؛ حدد العملية واستأنفها لاحقًا. الطلب غير المؤكد بعد انقطاع يُحفظ Unknown ولا يعاد تلقائيًا. أي Unknown أو قيد أو خطأ شبكة/HTTP أو رد غير متوقع يوقف X ويمنع طلبات جديدة حتى مراجعة تقنية؛ لا يوجد زر لتجاوز القيود. الإلغاء أثناء انتظار الفاصل فوري، والطلب الجاري قد يحتاج حتى انتهاء مهلة 15 ثانية.
- **Available إشارة API أولية فقط**. أبلغ المستخدم بتعارض `hzwu9`: أعاد API Available مرتين، ورفضته واجهة تغيير الاسم رغم غياب الملف العام. هذه الحالة لم تُحل، ولا تُحجز برمجيًا ولا تُعاد كتابة استجابتها. لا يملك نموذج السجل الحالي واجهة لتسجيل تعارض تحقق يدوي؛ تُحفظ النتيجة الأصلية مع التحذير، وتبقى المقارنة اليدوية خارج الأداة. تُحفظ الأدلة المنقحة وبصمة الأصل والسبب والتوقيت، ولا تُستنتج الإتاحة من ملف مفقود أو HTTP 200.
- تجربة `experiments/x-username-poc/` ذات 100 طلب محفوظة دون تعديل أو إعادة تشغيل حي أو استيراد تلقائي إلى سجل التطبيق. أرقام تجربتها لا تثبت دقة عامة أو استقرارًا طويلًا.

لبداية حية صغيرة يقوم بها المستخدم: اختر X ثم كمية **3** بطول **8** مع فاصل **5 ثوانٍ**، عاين ثم ابدأ، راقب الإيقاف والنتائج، وصدّرها وقارنها يدويًا بواجهة X دون حفظ اسم أو إنشاء حساب. لا تبدأ مسحًا كبيرًا من نجاح هذه العينة.
