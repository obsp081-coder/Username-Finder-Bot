## Local large-file search — 2026-11-06

- Added a sixth main tab, `البحث داخل الملفات`, after Instagram, preserving the five existing tab indexes. Arabic RTL controls select/add/remove/clear files, display sizes, enter literal text, choose a maximum (default 100; presets 10/100/1000; custom 1–100000), start/cancel, and show current file, completed files, occurrences, processed bytes and measured elapsed time. `QAbstractTableModel`/`QTableView` stores lightweight coordinates rather than complete source lines. Results remain in memory, ordered by selected file and byte position, without database jobs, indexes, caches or content logging.
- Search uses sequential 1 MiB binary blocks, C-level `bytes.find/count/rfind`, a query-sized overlap and strict incremental UTF-8 validation. It does not parse JSON, normalize text or interpret regular expressions. Matches are case-sensitive and overlapping occurrences count separately. Supports UTF-8/ASCII, optional UTF-8 BOM, LF/CRLF, `.json/.jsonl/.txt` and other valid UTF-8 text extensions. Binary NUL and invalid/UTF-16/UTF-32 input yield explicit errors; after an early limit the unexamined remainder is not validated. Queries must be nonempty single-line literals, at most 65536 UTF-8 bytes. Line and within-line byte positions are one-based; absolute file offsets are zero-based. BOM is encoding metadata, excluded from first-line text/column counting.
- The configured occurrence limit stops matching/validation at the final required occurrence, including repeated occurrences within one line. A read may already have prefetched at most one block beyond that position; `bytes_read` and `bytes_processed` are reported separately. The limit message states that additional unchecked results may exist. Actual complete EOF is distinguished from early stop. Two standard executor workers isolate search and source viewing; an eight-batch queue (128 matches/batch), timed GUI draining and throttled progress provide backpressure. Cancellation and application shutdown release owned readers/workers without touching other processes.
- Source rows retain canonical path, file identity/version, line start and match byte offset. A selected result validates identity/size/time, scans only its original line off the GUI thread and loads exact text on demand. The read-only LTR viewer supports mouse selection, Ctrl+C, selection/full-line copy, path/line copy and selected-occurrence highlighting. Original characters are retained for copying even where Qt normalizes control separators. LF/CRLF terminators are excluded explicitly. Lines up to 256 KiB display whole; larger lines are transparently paged in 64 KiB UTF-8-safe ranges with previous/next/jump access to the complete content. Full-line clipboard copying is limited to **4 MiB**, with an explicit explanation; larger lines remain fully readable page by page. No silent truncation or persistent source copies.
- Native Windows/Python 3.14 testing exposed inconsistent legacy `st_ctime_ns` semantics between path `stat` and handle `fstat` after rewrites. Identity checks use consistent Windows birth time plus device/inode, size and nanosecond mtime; normal modifications and moved/missing sources are rejected instead of displaying stale results. Metadata checks are not cryptographic snapshots: deliberate same-size edits with forged timestamps may evade detection. Cancellation cannot interrupt an OS read that has not yet returned. Case-insensitive/multiline queries and alternate encodings are not implemented.
